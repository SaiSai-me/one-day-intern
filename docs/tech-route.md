# 一日实习生 · 技术路线(v2)

> 对应产品定义:[一日实习生.txt](../一日实习生.txt)。命令层细节见 [lark-cli-toolkit.md](lark-cli-toolkit.md),引擎规范见 [engine/ENGINE.md](../engine/ENGINE.md),包格式见 [pack-spec.md](pack-spec.md)。

## 一句话架构

**引擎是说明书,剧本是分幕的提示词弹药,agent 是玩家自带的主机,飞书是画面,平台是发行方+直播间。**

```
┌─ 平台 web/(发行方+直播间)─┐        ┌─ 本地 Runner(玩家自带主机)────────┐
│ Next.js + Supabase          │ 下载  │ 任意本地 agent(Claude Code 等)     │
│ ① 实习包市场:画廊/上传/下载 │ ───→ │  ├─ 引擎 ENGINE.md(agent 中立)     │
│ ② 观战直播面板 /runs/<id>   │        │  ├─ 实习包 packs/<id>(分幕数据)    │
│    ↑ opt-in 状态上报(RPC)   │ ←──── │  └─ lark-cli(手)+ runs/(存档)     │
└─────────────────────────────┘        └───────────────┬────────────────────┘
        ↑ 创作者上传 zip                                │ im/calendar/task/docs/event
                                                        ▼
                                              玩家的真实飞书(舞台)
                                        拉群、派活、吵架、评审、摸鱼 → 日记
```

## 体验模型:导演-演员-舞台(剧本杀 DM 模式)

| 角色 | 对应物 | 性质 |
|---|---|---|
| 剧本册子 | 实习包:幕结构/人设/任务/判定 rubric | **写死**,创作者定义 |
| 导演 | 引擎确定性部分:时钟触发幕、维护世界状态、执行判定 | 确定性规则 |
| 演员 | LLM 即兴:对白、接插话、评审点评 | 即兴,受人设卡约束 |
| 舞台 | 飞书(群聊/卡片/日程/任务/文档) | 玩家唯一交互面 |

**三栏契约**(什么写死/什么即兴/玩家怎么输入)是产品定义的一部分,详见 [pack-spec.md](pack-spec.md)。关键设计:**沉默也是输入**——已读不回触发摸鱼判定与 NPC 反应,单机剧情永不卡死。

## 引擎核心机制(为什么是"真游戏"而不是"播放器")

1. **常听模式主循环**:引擎默认竖着耳朵听(`event consume --timeout <距下一幕>`);玩家任何时刻插话都有人接,幕是背景里自动到来的钟声。
2. **双通道感知**:WebSocket 事件流当门铃(1-2s 到达),`im +chat-messages-list` 按游标补漏当账本——AI 思考期间的消息一条不丢。玩家发言到 NPC 回怼全程 5-15s,恰是真人同事节奏,延迟即演技。
3. **世界状态 state.json**:幕进度/量表(好感度、摸鱼指数)/跨幕记忆摘要/分支旗标。它同时是即兴的记忆(上午吵架下午记仇)、判定的输入、断线续跑的存档。
4. **渐进装填**:幕文件到幕才读——省上下文,也防 AI 提前知道结局演砸。
5. **判定走 rubric**:量表增减规则写死在幕文件,日记只能来自 log.jsonl,不得虚构。

## 玩家动线(边界钉死)

| 阶段 | 在哪 | 频率 |
|---|---|---|
| 环境配置 | 终端 + 飞书开发者后台 | 仅首次 |
| 逛街/下载/上传 | 平台网站 | 每次换包 |
| 开机/关机/创作 | AI 终端(一两句话) | 每局 |
| **玩游戏(全部剧情)** | **只在飞书** | 一局的 95% |
| 围观别人上班 | 平台直播面板(可选) | 随时 |

## 三个组件与选型理由

### ① 实习包 —— 纯数据,分幕提示词包
安全(不下发可执行代码)、创作门槛低(写 Markdown 就能出包)、可拆积木复用(内容飞轮)。格式见 pack-spec v2。

### ② 引擎 —— agent 中立的说明书
[engine/ENGINE.md](../engine/ENGINE.md) 是单一事实源;`.claude/skills/one-day-intern` 只是 Claude Code 适配器,其他 agent(Codex CLI/Gemini CLI 等)以系统指令/AGENTS.md 方式引用同一份规范。最低 agent 要求:能跑 shell、能按说明书行事、能长循环或从 state.json 续跑。**运行算力归玩家,平台零推理成本**——引擎的定义权与发行权归平台,运行不经过平台服务器。

### ③ 平台 —— 发行方 + 直播间
- **市场**:Next.js + Supabase(intern_packs 表 + 公开桶),像素蓝白视觉
- **直播面板**:引擎经受限 RPC(run_key 鉴权)opt-in 上报幕转场与量表 → `/runs/<id>` 实时展示当前幕/量表仪表/名场面时间线;局终凝固为日记回放页。**观战链接是社交分发物**(围观即拉新)
- 隐私:上报默认关,开局询问;绝不上报凭证与玩家 open_id

## 认证与安全模型

| 身份 | 扮演 | 授权 | 备注 |
|---|---|---|---|
| bot | 全体 NPC | 后台开 scope,无需扫码 | 卡片署名+配色区分多角色(单 bot 硬边界) |
| user | 玩家 | OAuth 扫码,可增量 | 玩家凭证只存本机,平台不经手 |

bot 感知范围仅限它在场的会话 → 开局所有剧情容器(群/私聊/文档)必须由 bot 创建。

## 已验证的技术边界(冒烟测试实录)

- `event consume`:WebSocket 连通,NDJSON 流,有界消费契约可用 ✅
- bot 发消息/建群/建日程/派任务:dry-run 全通过,真发消息成功 ✅
- `task +create --due` 只收 ISO 8601(--help 的 relative: 格式是坑)⚠️
- `card.action.trigger` 需后台手动开"回调配置",否则静默收不到 ⚠️
- 沉浸模式(真实 8h)受上下文/终端常开/成本三重约束 → **产品默认压缩模式(15-20min)**,沉浸模式依赖 state.json 续跑

## 风险与对策

| 风险 | 对策 |
|---|---|
| agent 中断 | state.json 每次变化写盘;"继续上班"一句话续跑 |
| 消息漏收 | 双通道:事件门铃 + 消息列表游标补漏 |
| NPC 复读 | `--idempotency-key <pack>-<beat>-<seq>` |
| scope 受限 | 幕文件声明降级演法(如无 vc → 群聊模拟开会) |
| 陌生包安全 | 包为纯数据;引擎白名单幕类型;写操作确认规则 |
| 直播隐私 | opt-in;上报字段白名单 |
