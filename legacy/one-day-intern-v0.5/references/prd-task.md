# “短视频发布体验”MVP · 终极评审任务规则

## 给玩家的任务说明

由kris姐在群里发出：

> 你的唯一任务是完成一次 MVP 终审。请先在产品终审室提交一份五点式终审陈述，不需要写长文档：
> 1. **问题**：你要解决什么，而不是要做什么功能？
> 2. **用户与场景**：谁在什么情况下遇到这个问题？
> 3. **成功指标**：上线后看什么数据判断有效？
> 4. **MVP 范围**：这周只做哪 1–3 件事？
> 5. **非目标与风险**：这次明确不做什么，最需要防什么？

允许玩家使用自己的结构，只要语义覆盖这些问题。不要向玩家泄露下方评分细则。

## 评审 rubric

结合终审陈述和 E07 答辩原文评分，总分 0–5：

- 问题定义清楚，区别于功能描述：1 分。
- 目标用户和触发场景具体：1 分。
- 成功指标与目标一致，不只看曝光或点击：1 分。
- MVP 范围足够小，且能形成最小验证闭环：1 分。
- 说明至少一个非目标、隐私、误发布或内容安全风险：1 分。

得分至少 3 分则评审通过。答辩可以补足终审陈述中缺失的一项，但必须是玩家亲口补充。

任务只允许完成一次：

- E01 创建唯一飞书任务；E03、E04、E05、E06、E07 的确认结论写入本地 `task_progress`，再以完整、确定性的任务描述快照整体同步，禁止追加非幂等评论。
- E05 提交时只保存 `artifacts.review_brief`。
- E07 评审通过时才把飞书任务标记完成，并把 `tasks_completed` 从 0 改为 1。
- 未通过则保持 0，不能重复累计。

## 评审弹药

| 缺失或冲突 | NPC 追问 |
|---|---|
| 只说“简化发布页”，没有问题 | Vincent：“你是在复述方案。用户的问题是什么？” |
| 目标用户是“所有创作者” | Aria：“第一次发校园 vlog 的人和日更博主，是一个场景吗？” |
| 指标只有 DAU、曝光或点击 | Vincent：“这些涨了，为什么能证明问题被解决？” |
| 同时重做剪辑器、AI 自动成片、全平台分发、热点预测 | Ethan：“这是 MVP，还是明年路线图？” |
| 弱化可见范围或位置提示 | Aria：“发得快，不等于让人不小心把视频公开给所有人。” |
| 没写非目标 | Ethan：“下周你加需求时，我拿什么拦你？” |

## 技术约束

Ethan在 E06 给出的估算是固定事实：

- 重做剪辑器与模板系统：至少 4 周，需要改造渲染和草稿兼容。
- 多平台一键分发：至少 2 周，还受外部平台接口与审核规则限制。
- AI 自动成片、标题生成和热点预测：至少 3 周，并存在误导、版权和内容安全风险。
- 复用现有剪辑器，增加封面帧快选、精简发布页、发布前预览与可见范围确认、失败断点续传：5 天可出 demo。

合理 MVP 可以不同，但必须尊重上述约束并说清验证目标。
