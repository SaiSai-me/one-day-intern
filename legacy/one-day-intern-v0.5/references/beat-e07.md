# E07 · 终极评审：交付唯一任务

## 目标

主工作群是产品终审室。创建评审日程，按玩家真实终审陈述和答辩评分；这是开局唯一飞书任务的唯一完成条件。

## 工具动作

1. 读取 `prd-task.md`，作为终审 rubric；读取 `artifacts.review_brief`。
2. 按 CLI 契约创建 `⚔️ 短视频发布体验 MVP 终极评审`，开始时间取当前时间后 5 分钟，时长 20 分钟，邀请玩家，动作键为 `E07.calendar.create`。
3. 验证并把日程 `event_id` 追加到 `artifacts.calendar_event_ids`。
4. 发送评审消息包：Vincent针对目标/指标、Aria针对用户证据/风险、Ethan针对范围/非目标各问一条；每条只针对草案真实缺失项。
5. kris姐先在导师工作台发一条 30 秒“答辩顺序”提示：`【Mentor】kris姐 按“结论→证据→取舍”答。你不需要反驳所有人，只要守住自己的判断。`；评审中最多挡一次刀，不能替玩家回答。

## 等待输入

问题发完后在产品终审室等待玩家答辩 150 秒。玩家可一次回答全部，也可连续回复；只进行一轮集中答辩。

## 判定

1. 结合 `review_brief` 与答辩，按 0–5 分 rubric 逐项评分并写日志。
2. 答辩补足的内容必须由玩家亲口说出，不能由 NPC 推断。
3. 得分至少 3 分则通过：写 `flags.review_passed=true`；把逐项分数和评审结论写入 `task_progress.E07`，整体同步任务描述快照；再按 CLI 契约使用 `artifacts.task_id` 的 GUID 完成任务，验证为 `done` 后才把 `tasks_completed` 改为 1。
4. 得分不足 3 分：写 `flags.review_passed=false`；kris姐在导师工作台给出一句最关键的可修订建议，把“本次未通过及缺口”写入 `task_progress.E07` 并同步任务描述快照，任务保持未完成，但剧情继续。
5. 玩家主动引用数据、用户原话或明确取舍时，`boss_affinity +1`。
6. 玩家有理有据地拒绝不合理范围时不视为吵架；只有人身化对抗或完全忽略约束时才增加 `fights`。

## 沉默兜底

按现有终审陈述原文评分；陈述为空则 0 分。`slack +2`，kris姐只帮助团队收敛到能继续讨论的最小范围，不伪造通过。
