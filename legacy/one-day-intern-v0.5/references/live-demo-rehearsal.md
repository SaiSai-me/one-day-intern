# 演前检查与恢复

只给主持人和运行器看，不写进飞书。主讲 5:40、预留 20 秒；新短版 cue 不自动结业。旧 timed 存档仍按原截止收尾。

## 准备好再交给演示者

- 唯一活动 cue 存档已指定，正式文档原 URL 与用户正文保留；新局复用既有三群和唯一任务，有 source_run_id 回溯。
- 群名没有彩排或局号；所有 NPC 前缀为 `【职位 姓名】`。任务描述、评论、历史 bot 消息中可编辑的场外措辞已改成工作语言，原消息编辑前快照在本地；用户自己发的消息不修改。
- 任务真实链接可打开；飞书「更多 → 任务 → 我负责的」可见，空心圆就是提交。不要只给 PRD 链接却不告诉用户去哪交。
- PRD 最新正文与 revision 已读，评论落在真实缺口；不能要求已完善文档故意退回 2/5。追加稿与现有正文相容。
- 角色和开场有真实发送回执，停在 Vincent 让实习生定范围的一句。`demo.stage=prepared`、paused=true、deadline=null、heartbeat_id=null。
- 交给主持人一份带实际群/任务/文档链接的操作卡，包含三段聊天输入和一段追加正文，逐个说明去哪粘贴。文件放 runs，发布包不含账号资源链接。

## 两次完整计时检查

每次记录开始/结束、三次本人输入 ID、NPC 响应耗时、提交→验收耗时、文档前后 revision 与正文变化、评论解决回查、任务评审快照。逐字旁白加真实切屏 ≤5:40 才算时长通过；测试通过不代替真实演出。

不计时走通只记录「操作闭环已验证」，不虚构六分钟达标。预写台词记 presenter_script。备用结果与本次结果各有真实链接/快照；复用同一 Docx 修改之后，旧版不能冒充当前独立备用成果。

## 恢复与异常

- prepared 放置几天：仍暂停，无队列发言、无输入消费、无超时结业。
- 活跃时暂停：停止主动消息与评审写入、停用 heartbeat、释放租约；继续后不重建对象、不重播已发对白，保留三次沟通完成到哪一步。
- 自动队列每阶段有限且会去重；阶段变化后丢弃上阶段没发的背景对白。pending 发送先通过真实消息回查认领，不能重复刷屏。
- 沉默 60 秒：自动停在原进度，只在 Codex 提醒，飞书不说「超时」或代演示者决定。
- 直接点任务但未做三次沟通：保留完成信号，先接完实际沟通；不能把 task done 算沟通已完成。
- 只改评论导致 revision 增加、正文未改：不能验收。提示具体待改句，不替玩家输入。
- 读失败、重复事件、重复完成、双执行者：不误判通过，不重复写评论/消息/任务。作用于唯一 GUID、原 Docx 与评论 ID。
- 旧 completed/aborted 记录保持历史；新准备用新本地 run_id 关联同一套对象，不重置旧时钟或伪造旧局成功。

## 链接记录格式

`runs/<run_id>/presentation-links.md`：公司群、老板、导师、唯一任务、正式文档、断点、第一条预写输入、本地回执位置。获取不到的链接明确写未取得，不拼造分享 token。
