# E02 · 晨会：先看数据，别急着画功能

## 目标

主入口是导师 Chat。创建晨会日程和一张正式飞书数据看板，让玩家先阅读看板，再写出一张“问题卡”；不得用群消息逐条播报 KPI。

## 工具动作

1. 按 CLI 契约的“创建日程”创建 `☀️ 创作发布产品组晨会`：开始时间取当前时间后 5 分钟，时长 15 分钟，邀请玩家，动作键为 `E02.calendar.create`。
2. 验证并把日程 `event_id` 追加到 `artifacts.calendar_event_ids`。
3. 读取 `data-dashboard.md`，按其 typed 数据、样式、图表、幂等和回读协议创建 `青橙视频 · 短视频发布体验数据看板 · <run_id后六位>`。
4. 只有 `artifacts.data_dashboard.status="ready"` 后才发送本幕消息：
   - 老板 Chat / Vincent：`【产品总监】Vincent 先别急着改页面。看完数据后告诉我：最值得先解决的是哪个问题信号，为什么？`
   - 导师 Chat / kris姐：`【Mentor】kris姐 数据都在这张看板里：<dashboard_url>。先看 KPI、口径和图表，再回我一张三格问题卡：谁受影响、卡在哪里、哪条数据支持。`
5. 不在 Chat 中复述 41%、47% 或 18%，不把看板内容拆成多条消息。

## 等待输入

等待导师工作台的玩家文字 120 秒。允许提出判断、疑问或补充数据需求。

## 判定

- 玩家识别三个指标分母不同、数据只能说明问题信号、需要明确用户/场景或补充定性证据等任一有效洞察：写 `flags.data_literate=true`，`boss_affinity +1`；kris姐必须针对玩家原文给一条具体反馈，并要求补上缺失的“谁”或“证据”。
- 玩家直接开始列功能：kris姐先把功能改写成问题假设示范一次，再等待 60 秒让玩家自己改写；能修正则同样记为有效。
- 将玩家原文和核心判断写入 `memory`，供 E03 使用。

## 沉默兜底

kris姐在导师 Chat 发送 `【Mentor】kris姐 看板链接还在上面。我先给个问题卡起点：有一批进入发布页的新手没有完成发布；请把它改成“谁在什么场景卡住，并由哪条指标支持”。`，`slack +1`。不得在兜底消息中复述全部 KPI。
