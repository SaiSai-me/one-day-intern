# 主持人操作稿：5:40，预留 20 秒

这是演出操作稿，放在 Codex。飞书里全部说角色的工作语言。开始前所有对象、台词、任务入口、正文基线和评论均准备好，停在老板要求实习生牵头的地方。你不需要临场编答案；可复制输入见 [材料](../assets/live-demo-materials.md)。

整场只证明三件事：这是真实工作冲突，玩家的判断会改变同事行动，结果会落到可检查的文档和任务里。不在前三分钟解释技术；先让观众看见一次完整的工作闭环，4:05 再回答它怎么做到。

开播前只做一件事：确认公司群停在 `【产品总监 Vincent】发布体验这期，自动成片和全网同步也一起估一下。实习生，你来牵头，今天把范围定了。`。运行器此时 paused，没有计时和后台消息。

## 手边操作顺序

Codex「继续」→ 公司群输入 1 → 老板 Chat 输入 2 → 公司群输入 3 → 原文档末尾追加输入 4 → 飞书「更多 → 任务 → 我负责的」勾选标题前的空心圆 → 反馈。

消息发完立即切下一界面，不盯着输入框等。运行器保持活跃、无需回 Codex 发「好了」。任何时候想停，在 Codex 发「暂停」；再发「继续」从断点接演，期间消息不重播。

当前正式文档已写过完整五点式方案时，只追加「验收约定」，不能为了戏剧效果清空用户改好的内容或假称旧稿 2/5。每次演出都依据真实基线和本次实际提交。现场如果改变了预写答案，NPC 必须跟着实际内容走；可以未通过，不可以为了卡时强行圆满。

## 等待与口径

主讲 5:40 是人工讲解加切屏预算，不用超时自动通过来保证。到 3:40 仍未验收，主持人明确说「这次还在处理，我先展示提前跑通的一次结果」，只打开已记录的真实备用成果。若同一文档已继续修改，旧回执只代表此前那次结果；不能把当前页面冒充独立备用成品。

准备好后放置几天不影响进度。开播本身不是「继续」信号；只有你明确发送继续才启动这一段。How 展示真实文件和回执，不新增概念网页。
