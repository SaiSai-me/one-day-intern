# 实习开始前：飞书权限准备

在新局创建任何 Chat、文档、任务、日程或数据看板前，先向用户展示本清单。用户明确“开始实习”已授权创建本局资源，但不等于应用已经具备飞书权限。

## 用户需要完成的授权

在 Codex 对话中执行 `lark-cli auth status --json --verify` 检查 user 身份。未登录、未验证或缺少 user scope 时，停止初始化并使用 `lark-shared` 的 split-flow 发起**缺失 scope**或相关业务域的增量授权；展示原始授权链接和二维码，等待用户完成授权后再继续。

本局 user 身份需要能够：

| 能力 | 用途 | 推荐授权域 |
|---|---|---|
| 当前用户与联系人读取 | 识别玩家、必要时查询姓名 | `contact` |
| 群聊消息读取 | 读取玩家在三个 Chat 的回复 | `im` |
| 任务读写 | 创建、回查、更新、完成和重开唯一任务 | `task` |
| 日历读忙闲与创建 | 创建晨会和终极评审 | `calendar` |
| 电子表格创建、读写和图表 | 创建并验证数据看板 | `sheets` |
| Landing 文档读取 | 在开局验证玩家可见的说明文档 | `docs` |

优先按错误返回的 `missing_scopes` 发起最小授权。无法从当前 CLI 输出可靠映射时，可使用：

```bash
lark-cli auth login --domain contact --domain im --domain task \
  --domain calendar --domain sheets --domain docs --no-wait --json
```

不要把授权链接、device code、token 或 secret 写入 `state.json`、`log.jsonl` 或飞书消息。

## 管理员需要配置的应用权限

### 对外名称与实习昵称

- NPC 消息顶部显示飞书应用的机器人名称；正文中的 `【Mentor】kris姐` 等前缀只负责区分角色，不能覆盖消息发送者名称。群名、CLI 本地配置名与应用名称也不能混为一谈。
- 本实习的推荐应用名称为“一日实习生”。希望隐藏人名时，在飞书开放平台由该应用管理员修改应用/机器人对外名称，按后台提示使变更生效；也可由用户明确选择并配置专用应用。不要自动替用户创建新应用或切换账号。
- 创建本局资源前检查 `auth status --json --verify` 的 `identities.bot.appName`。若玩家要求匿名而当前名称仍含其不愿展示的人名，先停止外部写入并说明需要改名；不能仅改正文前缀就声称已隐藏发送者姓名。修改后重新读取验证，不发送测试消息来验证。
- `player.name` 是实习昵称，默认“实习生”，只有玩家明确指定称呼时才更新。台词、文档标题和日记使用此昵称；不主动传播接口返回的账户姓名。玩家自己的飞书头像、资料名，以及任务负责人、文档协作者等飞书原生界面仍受飞书账号资料控制，实习昵称不能替它们匿名。

本局 NPC 是同一个 bot。用户授权不能补足 bot 的应用权限；应用管理员必须在飞书开发者后台为该 bot 开通并发布相应权限。实际 scope 名称和申请入口以 CLI 错误中的 `console_url` 与 `missing_scopes` 为准。

bot 需要能够：

| 能力 | 用途 |
|---|---|
| 创建和管理群聊 | 创建公司群、导师 Chat、总监 Chat，并把玩家加入群聊 |
| 发送群消息 | 发送 NPC 台词、提示、通知和结束消息 |
| 接收群消息事件 | 监听 `im.message.receive_v1`，仅用于唤醒后回查消息 |
| 创建与读取 Docx | 创建 PRD 模板、读取提交后的文档 revision 与 block ID |
| 云文档评论 | 写入和解决唯一一条局部评审评论 |

若首次创建 company 或发送 HR 欢迎消息失败，保留 `initializing`、动作回执和已创建资源；把 CLI 原样的 `console_url` 提供给管理员，说明需要开通 bot 权限后再让用户发送“继续实习”。不要重新建群、不要自动删除资源、不要用 user 身份替 bot 绕过失败。

## 资源访问设置

- Landing 文档必须保持组织内获得链接可读；玩家只需阅读，不需要编辑。
- PRD 模板由 bot 创建后，玩家必须获得编辑权限；读取创建返回的 `permission_grant.status` 验证。若玩家无法编辑，停止在提交前并明确说明需授权该文档。
- bot 必须能读取和评论 PRD；若创建结果显示 bot 无法评论但玩家能编辑，可把一次反馈降级为总监 Chat，并在状态中记录原因。
- 晨会和终极评审创建前先查玩家忙闲；若冲突，询问玩家是按剧情时间创建还是跳过该日程，不能静默改时间。

## 开局提示与恢复

首次启动前，在 Codex 对话中简要提示：

> 开始前会检查飞书 user 授权和 bot 应用权限。若缺少权限，我会在创建任何资源前停止，并给出授权链接或管理员配置入口；完成后说“继续实习”即可原地恢复，不会重复创建群、文档或任务。

权限错误时，先区分：user 缺 scope、bot 缺 scope、还是某个具体文档/日程的访问权限。只给对应的最短修复方式；修复后以触发错误时的原身份重试同一动作。
