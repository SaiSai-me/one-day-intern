# E05 · 终审草案：把判断写成可评审陈述

## 目标

主工作群是产品终审室。玩家开始完成开局领取的同一个终极任务：提交一版可被挑战的终审陈述，而不是被分配第二个 PRD 任务。

## 工具动作

1. 读取 `prd-task.md`，但将其作为终极任务的“终审陈述模板”，不要创建任务。
2. kris姐在导师工作台发送：`【Mentor】kris姐 你不是要写一篇 PRD。终审只需五个判断：问题、证据、指标、范围、非目标。先写骨架。`
3. Vincent在产品终审室发送：`【产品总监】Vincent 把第一版发这里。它可以不完美，但每句话都要能被追问。`
4. kris姐在产品终审室发送一个短模板：`【Mentor】kris姐 格式：①谁在什么场景卡住；②哪条证据；③用什么指标；④这期做什么；⑤明确不做什么。`
5. 玩家提交后，kris姐只针对最薄弱的一格给一次具体反馈，并要求一次小修订；不替玩家写完整答案。

## 等待输入

等待产品终审室的玩家文字最多 240 秒。连续消息合并为同一份终审草案；内容较短时可先交骨架，再在导师反馈后补一次。

## 判定

- 将玩家所有连续草案与修订合并后写入 `artifacts.review_brief`，保留原文并记录日志。
- 将“已提交第一版终审陈述，待研发对齐”和草案摘要写入 `artifacts.task_progress.E05`，按 CLI 契约整体同步任务描述快照并写回执。
- 这里只记录提交，不增加 `tasks_completed`，不提前公布最终分数。

## 沉默兜底

kris姐在导师工作台发送 `【Mentor】kris姐 不用憋大文档。先发五行：问题、证据、指标、范围、非目标。`；再等待 60 秒，仍无输入则保持草案为空并推进，`slack +1`。
