# 开局前 Landing 对齐文档

这是每局模拟的第一份玩家可见材料，介绍岗位、协作方式和交付物。引擎必须先自行读取验证，再在 E01 公司群把同一个链接发给玩家；不能只在后台读取后直接进入业务剧情。它不是业务主题的事实来源，本局业务主题以 `world-and-personas.md` 为准。

## 固定飞书链接

- URL: https://wqua64v2akt.feishu.cn/docx/TCwtdW1EKoWtOUxtySbc9JJtnQb
- 类型: docx
- 访问: 组织内获得链接的人可阅读（`tenant_readable`）；玩家不可编辑
- 当前 revision: 38（运行时每局开始重新读取最新版本）

## 运行时要求

1. 新局创建任何 Chat、任务、日程或剧情消息前，先读取 [permission-setup.md](permission-setup.md) 并向用户展示权限提示，再使用 `lark-cli docs +fetch --as user` 读取该 URL。
2. 以最新文档正文确认其中包含岗位目标、三个 Chat 的分工和五点交付物；若其中仍有旧版产品命题、部门名称或角色名字，不得用它覆盖 `world-and-personas.md` 的“短视频发布体验”主题与当前角色命名。远端文档的旧名应由维护者同步；运行时发现不同则简要告诉玩家以本局角色介绍为准，不在游戏过程中改写这份只读说明。
3. 读取失败、权限不足或文档不可见时，保持存档 `initializing`，只向玩家说明如何打开链接或申请组织内阅读权限；不得创建本局资源或用剧情对白替代该文档。
4. 不把本文档内容复制到 PRD 工作文档；玩家的判断必须在任务绑定的 PRD 中完成。
5. E01 创建公司群后，把固定 URL 作为单行消息发给玩家，并明确请玩家先阅读。只有收到玩家在公司群的回复后，才写 `flags.landing_confirmed=true`；后台 `docs +fetch` 成功不等于玩家已经看过。
