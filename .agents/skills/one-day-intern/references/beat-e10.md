# E10 · 下班复盘：你是哪种产品经理

## 目标

基于真实日志生成本地 HTML 日记，回看玩家如何定义问题、做取舍和承担上线决策。

## 工具动作

1. 按 `SKILL.md` 的 E10 收尾状态机先写 `status=finalizing`，再调用 `scripts/render-diary.py` 生成并验证 `runs/<run_id>/diary.html`；所有玩家文本必须由脚本转义。
2. 正常完成时，HR 在入职台发送 `【人事】Chloe 本日实习流程完成！你今天交付的不只是一个方案，还有一串可以解释的判断。恭喜下班~`；提前结束时改为诚实的半日结束文案，不声称完成全流程。
3. 停用本局 heartbeat；只有日记、HR 通知和 heartbeat 停用均有完成回执后，才写最终 `completed` 或 `aborted`。

## 等待输入

无。

## 判定

日记必须包含：

- 玩家在 E01 设定的学习目标。
- 唯一终极任务的完成状态与最终评审结论。
- 玩家定义的核心问题或主要指标。
- E06 的 MVP 范围选择及研发确认/未确认的原因。
- E08 如何处理范围膨胀。
- E09 的上线决定和 `flags.product_outcome`。
- 来自真实玩家原文的 3–5 个名场面。

根据真实行为选择一个称号，不得只按单一选项机械判定：

- **问题侦探**：善于从数据和用户原话中重新定义问题。
- **范围守门员**：能明确 MVP、非目标和分期。
- **实验派 PM**：重视指标、灰度、监控和回滚。
- **增长赌徒**：多次选择先全量再看结果；评语应幽默但说明风险。
- **人形需求接收器**：多次无条件接下范围；评语要给出具体改进方向。
- **稳健型决策者**：在风险与速度之间给出清晰条件。

`boss_affinity >= 4` 时，Vincent可以追加：`【产品总监】Vincent 结论不一定都对，但每个决定你都说得清。有点意思。`
