# 产品经理一日实习 · 时间线

开局只读取本索引；进入某幕时再读取对应文件。

| 幕 | 产品能力 | 文件 | 出口 | 玩家要完成的事 |
|---|---|---|---|---|
| E01 | Landing 与项目对齐 | `beat-e01.md` | E02 | 阅读 Landing、认识所有同事、自我介绍并理解项目与最终交付；确认后才领取任务 |
| E02 | 数据判断 | `beat-e02.md` | E03 | 在导师工作台把业务数据整理成一张问题卡 |
| E03 | 需求澄清 | `beat-e03.md` | E04 | 在导师反馈后，把问题卡改写为可验证目标与指标 |
| E04 | 用户洞察 | `beat-e04.md` | E05 | 在用户研究台产出一张带风险边界的证据卡 |
| E05 | 终审草案 | `beat-e05.md` | E06 | 在产品终审室提交终极任务的第一版评审陈述 |
| E06 | 技术对齐 | `beat-e06.md` | E07 | 在研发质询后修订范围、非目标与验证方式 |
| E07 | 终极评审 | `beat-e07.md` | E08 | 用证据和取舍完成或保留该唯一任务 |
| E08 | 变更评审 | `beat-e08.md` | E09 | 把临时需求写成有理由的变更决定，而非随口回复 |
| E09 | 上线决策 | `beat-e09.md` | E10 | 给出带风险措施与回滚条件的上线决定 |
| E10 | 复盘 | `beat-e10.md` | 结束 | 生成基于真实行为的实习日记 |

唯一主路径：

`E01 → E02 → E03 → E04 → E05 → E06 → E07 → E08 → E09 → E10`

选择不再跳过学习环节，而是写入 `flags` 和终极任务快照，影响后续 NPC 态度、评审结果、上线结局和日记称号。E01 的主入口是公司群；E02–E03 使用导师 Chat，E04 的用户证据由运营在公司群提供、导师在导师 Chat 辅导，E05–E09 按各幕和 `runtime-compression.md` 路由。
