# E01 · Landing：认识团队，对齐今天的项目

## 目标

先让玩家看见 Landing 文档，认识所有协作角色，并理解公司、项目、工作方式与最终交付。玩家完成自我介绍和目标确认后，才创建 PRD 文档与终极任务；不得一进群就派业务题或要求做产品判断。

## 入口

本局只使用三个固定 Chat：`company`（🏢 创作发布产品组·公司群）、`mentor_dm`（🧭 【Mentor】kris姐（1:1））、`boss_dm`（⚔️ 【产品总监】Vincent（1:1））。不得创建旧版 `lobby`、`mentor`、`research`、`review` 四群。

## 阶段一：Landing 与团队见面

进入 E01 时写 `beat_phase="landing"`。本阶段只创建 Chat、展示 Landing、完成角色介绍与项目对齐，不创建 PRD 文档、飞书任务或日程。

### 工具动作

1. 确认开局前已经按 `landing-orientation.md` 成功读取 Landing 文档；未成功读取则停止，不创建任何 Chat。
2. 按 CLI 契约先创建 `company`，立即发送第一条 HR 欢迎消息作为 bot 建群/发消息能力探针；成功后创建 `mentor_dm` 和 `boss_dm`。每个 Chat 使用独立 UUID 和动作键 `E01.chat.create.<room_key>`，验证 `chat_id` 后立即写盘。
3. 依次发送下列单行消息；每条使用独立动作键，恢复时不得重复发送。

### 公司群：欢迎与 Landing

- HR：`【人事】Chloe 欢迎来到青橙视频创作发布产品组，我是Chloe，负责今天的入职流程、任务说明和下班复盘。先别急着接需求，我们先把人和项目认全。`
- HR：`【人事】Chloe 这是今天的 Landing 文档，请先打开看一下岗位、三个 Chat 的分工和最终交付：https://wqua64v2akt.feishu.cn/docx/TCwtdW1EKoWtOUxtySbc9JJtnQb`

### 所有人自我介绍

- 公司群 / 后端：`【技术负责人】Ethan 我是Ethan，负责剪辑草稿、上传和发布链路。你定范围，我报成本、风险和能不能按时交付。`
- 公司群 / 运营：`【运营】Aria 我是Aria，负责创作者运营和用户反馈。我会把年轻创作者为什么“拍了不发、发了又删”的一线证据给你。`
- 导师 Chat / kris姐：`【Mentor】kris姐 我是kris姐，你今天的带教。我的工作是帮你把模糊需求拆成问题、证据、指标和 MVP，但最后的决定必须由你来做。`
- 老板 Chat / Vincent：`【产品总监】Vincent 我是Vincent，创作发布产品负责人。终审时我会追问为什么做、成功怎么算、这次不做什么；结论可以不同，但必须有依据。`

### 公司群：项目对齐

- HR：`【人事】Chloe 今天的项目是“短视频发布体验”：不少新手已经剪完视频，却卡在封面、标题、话题、可见范围或上传重试，甚至发出后马上删除重来。`
- HR：`【人事】Chloe 你的任务不是马上画一个新发布页，而是先判断最值得解决的是谁的什么问题，再用数据、用户证据和技术约束收敛一个本周可验证的 MVP。`
- HR：`【人事】Chloe 最终交付是一份五点终审陈述：问题与用户、证据、成功指标、MVP 范围、非目标与上线保护。今天会依次经过数据判断、用户研究、技术对齐、终审和上线决策。`
- HR：`【人事】Chloe 现在轮到你啦：看完 Landing 后，请在公司群用一句话介绍自己，再说今天最想重点练产品判断、跨团队沟通、评审表达，还是自定义目标。`

## 等待输入

在 `company` 等待玩家文字 120 秒，使用 `onboarding` 检查点。接受自然语言，不要求固定格式；一条消息同时包含自我介绍和练习目标即可。玩家只说“看完了”时，也算完成 Landing 确认，练习目标采用默认值。

## 判定

- 收到玩家输入后写 `flags.landing_confirmed=true`，保存玩家自我介绍原文到 `memory`，把练习目标摘要写入 `flags.player_goal`。
- 玩家没有明确练习目标时，写 `flags.player_goal="完成一次有证据、有取舍的产品终审"`，不要追问第二轮。
- HR 在公司群用一句话回应玩家介绍；不得给玩家起冒犯性花名。
- kris姐在导师 Chat 确认：`【Mentor】kris姐 认识了。接下来我会先带你看数据，再由你定义问题；现在才正式开始干活。`

## 阶段二：创建工作对象

玩家完成 Landing 确认后，写 `beat_phase="assignment"`，然后才执行以下动作：

1. 按 `artifact-adapters.md` 创建唯一 PRD 模板 `短视频发布体验 MVP · 终审陈述`，保存文档 token、URL、revision 与权限结果，动作键 `E01.document.create`。
2. 创建并指派唯一任务 `完成「短视频发布体验 MVP 终审」`，截止时间取当前时间后 45 分钟，描述中包含 PRD 文档 URL、五项验收和“点击完成即提交”，动作键 `E01.task.create`。
3. 在公司群发送：`【人事】Chloe 项目已对齐，PRD 模板和终极任务现在发给你。先不用写答案；下一站，kris姐会带你看数据。`
4. 文档和任务均验证成功后写 `beat_actions_done=true`，进入 E02。

## 沉默兜底

120 秒到期仍无输入时，不声称玩家看完 Landing。写 `flags.landing_confirmed=false`、`flags.player_goal="完成一次有证据、有取舍的产品终审"`、`slack +1`。HR 在公司群发送：`【人事】ChloeLanding 链接先留在这里，我按默认目标帮你继续排好今天的流程；回来后随时可以补一句自我介绍。`随后进入 `assignment`，创建同一份 PRD 文档和终极任务，不重复介绍或另建资源。

## 恢复规则

- `beat_phase="landing"`：按动作回执只补建缺失 Chat 或补发未成功的介绍消息，恢复 `onboarding` 的原截止时间；不得提前创建任务。
- `beat_phase="assignment"`：只补做尚未成功的文档、任务和任务通知；不得重放 Landing 和自我介绍。
- E01 完成前始终保持同一个 `run_id`，不得因超时或恢复创建第二套 Chat、文档或任务。
